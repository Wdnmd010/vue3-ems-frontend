# 分页按钮圆形化报告（2026-11-09）

> 本次是对「按钮视觉调整」中第二项（紧凑型按钮）的修正：由 8px 圆角方块改为正圆。
> 只改 `client/src/style.css` 的分页相关规则，未动页面结构、长条按钮、导航、卡片与业务逻辑。

## 一、改动内容

| 元素 | 改前 | 改后 |
| --- | --- | --- |
| 页码（1、2、3…） | 8px 圆角方块 | **正圆 `border-radius: 50%`** |
| 当前页码 | 白底黑字方块 | 白底黑字**圆形**（`#FFFFFF` + `#171717`） |
| 上一页 / 下一页箭头 | 2px 圆角方块 | **正圆**、透明底、禁用态灰 `#4A4A54` |
| 长条操作按钮 | 胶囊 999px | **未改动**，仍为胶囊 |

固定尺寸确保圆不变成椭圆：

- 桌面：`32×32`（`width / height / min-width` 三者同值）
- 手机（分页 `small`）：`24×24`，与原有 small 尺寸一致，未放大

## 二、过程中发现并修复的问题

第一版只写了 `.el-pagination button { border-radius: 50% }`，实测**翻页箭头仍是 2px 圆角**。

原因：Element Plus 对 `.el-pagination.is-background .btn-prev / .btn-next` 有自己的规则，特异性（3 个 class）高于我的 `.el-pagination button`（1 class + 1 element），把圆角覆盖回去了。

修复方式：改用同等特异性的选择器 `.el-pagination.is-background .btn-prev / .btn-next`，并补上 `:disabled` 状态；同时把箭头的背景改为透明，避免出现「圆形里套一个方形底」的错位感。没有使用 `!important`。

## 四、样式规则（`style.css`）

- 页码与箭头：固定 `32×32`（small 为 `24×24`），`border-radius: 50%`。
- 未选中：透明底 + `--ems-text-secondary` 灰白字。
- 悬停：`--ems-input` 深灰底 + 亮一档文字，无动画、无发光。
- 当前页：`#FFFFFF` 底 + `#171717` 字 + 600 字重，并额外覆盖 `:active:hover` 防止鼠标悬停时掉回灰底。
- 禁用箭头：透明底 + `#4A4A54`，不参与悬停。

## 七、仍存在的限制

1. **未选中页码仍无法真机验证**：库里只有 10 条数据、每页 10 条，永远只有 1 页，分页只渲染一个「1」。规则（透明底 + 灰白字 + 深灰悬停圆）已写好，但要看效果需要 11 条以上数据。我没有造数据（会写库）。
2. 若页码出现两位数（如「11」），在 32px 圆内仍可容纳；三位数（100+）会偏挤，届时可把 `min-width` 放宽到 36px，但那会变成椭圆，需要同时改高度 —— 当前数据规模不涉及。
