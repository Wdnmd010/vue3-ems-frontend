# 纯前端改造总结（去后端 + localStorage）

- 日期：2026-11-15
- 改造范围：把 Vue3 + Element Plus + Express + MySQL 的前后端分离项目，改造为**只保留前端、数据存 localStorage、可部署 GitHub Pages** 的版本
- 结论：改造完成，`npm run build` 通过，全部业务功能在真实浏览器中验证通过，生产包在子路径 `/ems/` 下运行正常

---

## 一、架构变化

| 方面 | 改造前 | 改造后 |
|---|---|---|
| 数据存储 | MySQL（employees / departments / users 三张表） | localStorage（`ems.db` 单库 JSON，带 version） |
| 后端服务 | Express + mysql2 连接池，19 个接口 | 无（`server/`、`database/` 已删除） |
| 认证 | JWT + HttpOnly Cookie + bcrypt + 黑名单 | localStorage 会话（`ems.session`），仅演示 |
| Excel | 后端 ExcelJS + Multer，接口上传/下载 | 浏览器端 ExcelJS，直接读文件、直接生成下载 |
| 路由 | History 模式，需服务端回退 | Hash 模式（`#/employees`），静态托管不 404 |
| 构建 | `base` 默认 `/` | `base: './'`，可部署在任意子路径 |
| 部署 | 需常驻 Node 服务 + MySQL | 任意静态托管（GitHub Pages / Vercel / Nginx） |

接口层的函数签名与返回结构 `{ data: ... }` 全部保留，所以**四个页面（登录/仪表盘/员工/部门）的业务代码基本没动**，只换了数据来源。

## 三、数据层设计

```
localStorage
├─ ems.db       { version, users[], departments[], employees[], seq{} }
└─ ems.session  { id, username, loginAt }
```

1. **单一入口**：只有 `data/db.js` 直接操作 localStorage，页面与 api 层都不碰存储。
2. **版本迁移**：读取时统一走 `migrate()`，缺字段会补默认值、`seq` 会自动对齐现有最大 id；后续结构升级只需在这里加分支。
3. **只初始化一次**：`readDb()` 只在 `localStorage` 为空或损坏时写入种子数据，**不会覆盖已有数据**。
4. **自增序列**：用 `seq.department` / `seq.employee` 替代 MySQL 的 AUTO_INCREMENT。
5. **写即持久化**：每次增删改都「读 → 改 → 写」并立即落盘，刷新/关浏览器不丢。
6. **存储异常兜底**：隐私模式等场景 localStorage 不可写时，退回内存态并给出可读错误，不会白屏。

统计口径与原 SQL 对齐：部门分布含 0 人部门并按人数降序、性别分布把非男/女归入「未知」、近 30 天入职含今天且排除未来日期、最近入职 5 人未填日期的排最后。

## 四、登录说明

- 演示账号：`root / admin123`（写在 `data/seed.js`，登录页有提示，快捷登录卡片一键进入）。
- 登录成功后在 `localStorage` 写一条 session，路由守卫据此判断；退出登录清除 session。
- **这只是演示登录**：账号密码在本地明文存储、可被任何人查看和修改，不具备真实安全性，不能用于生产环境。原版基于 JWT + HttpOnly Cookie + bcrypt 的机制已随 `server/` 一并移除。

## 五、Excel 改造

| 能力 | 实现 |
|---|---|
| 下载模板 | 浏览器生成 xlsx Blob（表头样式、示例行、填写说明页与原版一致） |
| 导出 | `selectEmployees()` 取数后生成 Blob，页面原有 `saveBlob()` 触发下载 |
| 导入预览 | `FileReader` 读成 ArrayBuffer → ExcelJS 解析 → 逐行校验，返回 `{total, validCount, failedCount, errors}` |
| 确认导入 | 逐条写入 localStorage，单行失败不影响其它行，返回 `{total, success, failed, errors}` |

校验规则逐条保留：工号格式与唯一性（含文件内重复、与库里重复）、姓名/职位必填与长度、性别枚举、手机号/邮箱格式、部门必须存在、状态枚举、日期真实性（如 2026-02-31 会被拒）。表头缺失会在解析阶段直接报错。

ExcelJS 体积约 940 KB，已通过 `import('exceljs')` 拆成独立 chunk，只有在点「导入/导出/模板」时才加载，不影响首屏。

## 六、GitHub Pages 部署

1. `vite.config.js` 设 `base: './'`，产物用相对路径（`dist/index.html` 中为 `./assets/...`），部署在 `https://<user>.github.io/<repo>/` 子路径下无需改配置。
2. 路由改为 Hash 模式，刷新 `#/employees` 不会 404，静态托管不需要额外回退规则。
3. 仓库内置 `.github/workflows/deploy.yml`：推送 `main` 自动 `npm ci` + `npm run build` + 发布 `client/dist`。
4. 仓库 Settings → Pages → Source 选 **GitHub Actions** 即可。
