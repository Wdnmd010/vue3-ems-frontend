## 四、推送失败的原因与排查过程

### 失败现象

```
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

### 排查步骤

1. 直接 `git push` → `schannel: CRYPT_E_NO_REVOCATION_CHECK`。
2. 关闭吊销检查 `http.schannelCheckRevoke=false` → 仍失败。
3. 切换 `http.sslBackend=openssl` → `unable to get local issuer certificate`。
4. `curl -k https://github.com` → 200，说明**网络可达，但 TLS 被本地代理（`127.0.0.1:2519`）中间拦截**，证书链不被 git 信任。
5. 临时 `http.sslVerify=false` 后 `git ls-remote` 成功（返回空 = 仓库为空且可访问），证明远程地址与网络路径没问题。
6. 再执行 `git push` → 明确报「无法读取用户名」，即**纯粹缺凭据**。

### 环境补充说明

- 本机 `gh` CLI 未安装；无 `~/.ssh/id_*`；无 `~/.git-credentials`。
- 本机已安装 Git Credential Manager（`C:\Program Files\Git\mingw64\bin\git-credential-manager.exe`），
  人工在终端执行推送时会自动弹出浏览器登录，无需手动输入密码或 token。
- 排查期间使用的 `http.sslVerify` / `http.sslBackend` / `http.schannelCheckRevoke` 三项临时配置**已全部 unset**，
  仓库配置保持干净，不会影响后续正常推送。
