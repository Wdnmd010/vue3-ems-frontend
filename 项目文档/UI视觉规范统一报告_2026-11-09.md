# UI 视觉规范统一报告（2026-11-09）

> 目标：把散落的圆角、按钮、输入框、卡片样式收敛成一套可解释的全局规范，而不是继续「哪里不齐补哪里」。

## 一、检查总结：问题确实存在

改前全项目 `border-radius` 共 6 种取值，且同一类组件不统一：

| 改前 | 出现位置 | 问题 |
| --- | --- | --- |
| `6px` | `.el-tag` | — |
| `8px` | 按钮、输入框、头像块（`var(--ems-radius-sm)` 与硬编码混用） | 变量与硬编码并存 |
| `9px` | 顶栏 Logo、快捷操作图标块 | 凭空多出一档 |
| `10px` | 统计卡图标块、下拉浮层、消息提示 | 与 8 / 12 撞车 |
| `12px` | 卡片、表格 | — |
| `14px` | 弹窗、确认框（部分硬编码） | 与变量并存 |
| `999px` | 导航胶囊 | — |

同时：员工页卡片紧贴导航（无上边距），首页有 26px 欢迎区留白，两页顶部不一致。

## 二、建立的圆角规范（唯一来源）

`client/src/style.css` 的 `:root` 中定义，**页面与组件只引用变量，不再写死数值**：

```css
--radius-sm: 6px;    /* 小标签、徽标 */
--radius-md: 8px;    /* 按钮、输入框、下拉、日期选择、图标块 */
--radius-lg: 12px;   /* 卡片、表格容器、下拉/消息浮层 */
--radius-xl: 14px;   /* 弹窗、确认框 */
--radius-pill: 999px;/* 顶部导航胶囊 */
```

旧变量 `--ems-radius / --ems-radius-sm / --ems-radius-pill` 保留为别名，指向新变量，历史引用不会失效。

## 七、尚未解决 / 需留意

1. **按钮高度**：沿用 Element Plus 默认（32px；手机卡片操作用 small 24px）。没有强行改 `height`，因为改了会破坏 `size` 体系与触屏可点击区域。
2. **图标块 8px 偏方正**：38px 方块配 8px 圆角比之前的 10px 更「硬」，是为与按钮统一而做的取舍。如果你更想要柔和观感，单独把图标块调到 10px 只需改 3 处，不影响其他规范。
3. 分页第二页、增删改实际提交、账号密码登录仍未真实跑（受数据量与「不写库」限制），相关代码未改动。
4. `--ems-radius-lg` 这类历史别名仍保留在 `:root`，仅作兼容，页面已不再引用。

## 八、验收建议

2. 打开新增员工弹窗：弹窗外框 14px，内部输入框 8px，与页面输入框一致。
3. 看分页：当前页紫色方块 8px 圆角，与「搜索」按钮同圆角。
